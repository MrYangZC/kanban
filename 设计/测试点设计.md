# 测试点设计

> 依据：`设计/功能点梳理.md`（F1~F10）。用例编号 `T-<模块><序号>`，模块：A 通用层、B 账号、C 项目、D 概览、E 工作项通用、F 需求/任务页、G 缺陷页、H 详情协作、I 过程管理、J 度量、K 系统管理、S 专项。

## 一、测试策略

### 1.1 测试维度

| 维度 | 关注点 | 重点模块 |
|---|---|---|
| 功能正确性 | 主流程可走通、字段落库、列表回显、状态同步 | 全部 |
| 权限与越权 | 未登录、跨项目、项目内无权限、非管理员、超管绕过 | C / H / K |
| 状态机 | 合法边、非法边、反向、跳级、并发改状态 | E / G / I |
| 边界与异常 | 空值、超长、非法 UUID、非法枚举、缺参、重复提交 | A / E |
| 数据隔离 | 三表路由、子资源 `category`、跨类型查询合并 | E |
| 缓存一致性 | 改角色/成员/权限后立即生效 | C / K |
| 安全 | XSS（Markdown）、直链越权、路径穿越、注入 | A / H |
| 幂等与并发 | 收藏、拖拽、编号生成、重复创建 | C / E |
| 数据一致性 | 删除级联、归档后查询、审计字段 | E |
| 体验三态 | 加载 / 空 / 错误（含断网） | F~J |

### 1.2 优先级定义

| 级别 | 含义 | 执行时机 |
|---|---|---|
| P0 | 主干链路，坏了不能用 | 每次提测、每次上线 |
| P1 | 核心功能与权限，坏了影响业务 | 每次提测 |
| P2 | 边界、异常、次要功能 | 版本回归 |
| P3 | 体验与低概率场景 | 专项/探索 |

### 1.3 环境与数据准备

- 账号：超管 1、项目 OWNER 1、ADMIN 1、DEV 1、VIEWER 1、非成员 1。
- 项目：正常项目（含三套工作流：任务 4 节点 / 需求 6 节点 / 缺陷 6 节点）、空项目、已归档项目各 1。
- 数据：需求/任务/缺陷各 ≥ 20 条（含父子、含归档、含逾期），迭代 2 个（PLANNED/ACTIVE），里程碑 1、风险 1、公告 1、评论 ≥ 3 层、附件 ≥ 2。
